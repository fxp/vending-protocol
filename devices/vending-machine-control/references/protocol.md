# 某星XX800 / WM800 协议详解

## 帧结构

```
请求 (上位机 → 下位机)：
+------+------+--------+-----+------+--------+--------+
| 0xEE | 0x01 | addr×4 | cmd | len  | data×N | crc×2  |
+------+------+--------+-----+------+--------+--------+

响应 / 主动上报 (下位机 → 上位机)：
+------+------+--------+-----+------+--------+--------+
| 0xFF | 0x01 | addr×4 | cmd | len  | data×N | crc×2  |
+------+------+--------+-----+------+--------+--------+
```

- `addr`：4 字节大端，看物理拨码开关
- `len`：2 字节大端，**仅 data 部分长度**
- `crc`：设备**不校验**，但下位机自己发的是 CRC16-XMODEM 大端（poly 0x1021, init 0x0000, 无反射, 不异或）

## 完整指令矩阵

### ✅ 完全可用

#### `0x01` 查询版本号

请求：
```
data = [board_type:1B, reserved:1B=0]
       board_type: 0=电机控制板, 1=平台抓手板
```

应答：30B ASCII，含 trailing `\x00`，例：
```
"VX9.2.0-2403209.Z.0-260320\x00\x00\x00\x00"   ← 电机板
"XYP.3.0-210918P.T.3-260317\x00\x00\x00\x00"   ← 平台板
```

#### `0x05` 查询设备状态

请求：data 空。
应答：1B 状态码（见状态码表）。100ms 内回。

#### `0x24` 复位门 + 扫描货道

请求：
```
data = [reset_door:1B, scan_mode:1B]
       reset_door: 0=不复位, 1=复位
       scan_mode:  1=全部扫描, 2=仅扫描层数
```

应答（**实际格式，与 CSV 不同**）：
```
data = [reserved:1B=0, layers:1B, motors_per_layer:N×1B]
```

例：`00 07 03 05 05 05 06 06 06` = 7 层，每层 [3,5,5,5,6,6,6] 个电机。

**实测耗时 ~202s**，timeout 必须 ≥ 300s。

#### `0x28` 出货指令

请求：
```
data = [lane:2B BE, order_id:8B]
       lane: 货道编号（十进制平面编号，如 100, 101, 102, 200, 201...）
       order_id: 唯一订单号，建议用毫秒时间戳
```

应答：
```
data = [order_id:8B, status:1B]
```

**status 码表**（部分实测）：
- `0x00` 成功
- `0x08` 货道空 / 无法抓取（实测过）
- 其它码请实测对应硬件状态

期间会收到多个 `0xE1` 主动上报（见 `0xE1` 节）。

#### `0x29` 查货道有无电机

请求：
```
data = [lane:2B BE]
```

应答：
```
data = [前2字节:语义不明, status:1B]
       status: 0=有电机, 1=无电机
```

⚠️ **CSV 说前 2 字节是 lane echo，实际不是**。lane=100 echo=`00 00`，lane=1 echo=`00 01`。**只信第 3 字节**。

#### `0x2A` 复位下位机

请求：data 空。
应答：1B（0=寻原点成功，1=失败）。<1s 完成。

#### `0x2B` 全货道步数

请求：data 空。
应答（**实际格式，与 CSV 不同**）：
```
data = [layers:1B, motors_per_layer:N×1B, x_steps_per_lane:4B×total_lanes]
```

⚠️ CSV 写有 "Y 步数" 块（180 字节），**实际 152 字节**，没有 Y 步数。

例：7 层 36 货道 → 1 + 7 + 4×36 = 152B

#### `0x30` 查订单状态

请求：
```
data = [order_id:8B]
```

应答：
```
data = [dispense_ok:1B, picked_ok:1B]
       0 = 成功, 非 0 = 失败
```

不存在的订单号返回全 0。

#### `0x34` 光电传感器

请求：data 空。
应答：
```
data = [count:1B, states:N×1B]
       本机 count=5: 右/左/上/中/下
       state: 0=未触碰, 1=触碰
```

#### `0x35` 红外传感器

请求：
```
data = [ir_type:1B]
       0 = 平台竖红外
       1 = 平台横红外  ← ⚠️ firmware 不实现，应答 cmd 字段会变成 0x36
       2 = 防夹手红外
       3 = 层定位
```

应答：
```
data = [state:1B]
       0=未遮挡, 1=遮挡
```

#### `0x36` 红外超时 R/W

请求：
```
data = [op:1B, ir_type:1B, time:2B BE]
       op: 0=查询, 1=设置
       ir_type: 1=挡住最短, 2=非挡最短, 3=挡超时（皮带方案）
       time: 单位 ms
```

应答（op=0）：
```
data = [t1:2B, t2:2B, t3:2B]   挡最短 / 非挡最短 / 挡超时
```

应答（op=1）：1B（0 成功 / 1 失败）。

#### `0x37` 滤波值 R/W

请求：
```
data = [op:1B, value:4B BE]
       op: 0=读 X+Y, 1=设置 X, 2=设置 Y
       value: 滤波时间 ms (10-1000)
```

应答（op=0）：
```
data = ['X':1B, x_value:4B, 'Y':1B, y_value:4B]   共 10B
       注意 'X'/'Y' 是 ASCII 字符 0x58/0x59
```

应答（op=1/2）：1B（0/1）。

#### `0x38` 出货前检测原点 R/W

请求：
```
data = [op:1B, state:1B]
       op: 0=查询, 1=设置
       state: 0=关闭, 1=开启
```

应答：1B（op=0 时是当前状态，op=1 时是 0/1 设置结果）。

#### `0x39` 微动开关

请求：data 空。
应答：
```
data = [count:1B, states:N×1B]
       本机 count=6: 上限位/下限位/防夹手/大门/Y伺服/X伺服
       前 3 个: 0=未触碰, 1=触碰
       大门: 0=门开, 1=门关
       伺服: 0=正常, 1=异常
```

#### `0x65` 开取货门

请求：
```
data = [reserved:3B=0, no_pick_timeout:2B BE, normal:1B]
       no_pick_timeout: 不取货超时（秒），到时门会自动关
       normal: 0=非正常（即使平台不在原点也开门），1=正常（先把平台移到取货口再开）
```

应答：1B（0 成功，非 0 失败）。

期间收到 `0xE1` 上报。

#### `0xBD` 屏幕按键

请求：
```
data = [action:1B, op:1B]
       action: 0=停止, 1=运动
       op: 0=复位, 1=左, 2=右, 3=上, 4=下
```

应答：1B（0 成功）。

⚠️ **必须 stop → run 之间留间隔**，否则连续 run 可能被吞。

#### `0xE1` 取货口主动上报

下位机发：
```
data = [order_id:8B, action_code:1B]
       action_code:
         0x01 打开取货口
         0x02 关闭取货口（wm22 用）
         0x03 检测到拿走货物，门关闭成功
         0x04 平台回原点成功
```

**必须 ACK**：上位机回 `EE 01 ... E1 0001 [action_code] [crc]`，否则下位机重发 3 次。

`WM800Client.on_report` 会自动 ACK。

#### `0xE2` 大门主动上报（被动事件）

下位机发：
```
data = [action_code:1B]
       0x00 打开大门
       0x01 关上大门
```

不需 ACK（CSV 未要求）。

### ⚠️ 有响应但语义错

#### `0x04` 是否能出货

请求：
```
data = [lane:1B, push_if_open:1B]
       lane: 0xFF=跳过检测
       push_if_open: 0=不顶, 1=门没关紧时顶一下
```

应答：
```
data = [device_status:1B, has_goods:1B, can_dispense:1B, reason:1B]
       can_dispense: 0=可出货, 1=不可
       reason: 0x02 = 无电机（实测永远报这个）
```

⚠️ **不可信**：实际能出货的 lane 也报 reason=0x02。**直接发 `0x28`，不要预检**。

### ❌ Firmware 不实现

#### `0x23` 伺服重启 — 不实现

请求格式（参考用，发了无应答）：
```
data = [op:1B, time:1B]
       op: 0=关, 1=开, 2=重启
       time: 20-255 秒
```

实测无应答，伺服状态字节也不变。**禁止使用**。需要恢复用 `0x2A`。

#### `0x2C` 改货道步数 — 不实现

请求格式：
```
data = [count:1B, [lane:2B, x:4B, y:4B] × count]
```

实测无应答，0x2B 数据也不变。**禁止使用**。

#### `0x3D` 平台电机直驱 — 不实现

请求格式：
```
data = [action:1B, time:1B]
       action: 0=停, 1=动
       time: ≤60 秒
```

实测无应答 + 视觉确认平台一帧不动。**禁止使用**。

#### `0xBC` 每层偏移步数 — 不实现

请求格式：
```
data = [layers:1B, [direction:1B, steps:2B] × layers]
       layers=0xFF 表示查询
       direction: 0=向上偏移, 1=向下偏移
```

实测无应答（试过 4-7 种 payload）。**禁止使用**。

## 状态码表（0x04 / 0x05 共用）

| 值 | 含义 |
|---|---|
| `0x00` | 空闲 |
| `0x02` | 无电机 |
| `0x12` | 右/中/下限位未触碰 |
| `0x19` | 左限位被触碰 |
| `0x1A` | 上限位被触碰 |
| `0x1E` | 取货门没关紧（微动或电机损坏） |
| `0x22` | 竖红外被挡或损坏 |

非 0x00 表示设备处于异常或正在某种动作中。
